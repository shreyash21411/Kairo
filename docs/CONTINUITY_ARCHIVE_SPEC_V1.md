# VOIDZONE Continuity Archive Specification (v1.0)
## Portable Conversation Continuity Contract

> **Format Identifier:** `voidzone.continuity.archive`  
> **Schema Version:** `1.0`  
> **Status:** Ratified for Phase 1 (Hackathon Baseline)  
> **Integrity Algorithm:** SHA-256 (Canonical source normalization)  

---

## 1. Overview & Purpose

The **VOIDZONE Continuity Archive** is a provider-neutral, versioned, portable JSON data contract. It allows AI software development sessions to be captured, cryptographically hashed, validated, and transferred across different AI platforms (e.g. Claude → VOIDZONE → ChatGPT) without context loss or false metadata attribution.

### Architectural Guarantees
- **Local-First & Offline:** Archive creation, hashing, validation, import, and export execute entirely client-side. Zero external network requests, zero telemetry, and zero LLM dependencies are required.
- **Data Integrity & Immutability:** Raw transcripts are preserved verbatim. Original messages and sequence ordering are immutable.
- **Honest Provenance & Completeness:** Metadata clearly separates source-native data from user-supplied notes and VOIDZONE-generated heuristics.
- **Cryptographic Tamper Detection:** A deterministic SHA-256 hash covers the canonical source content. Changes to transcripts or message ordering trigger integrity errors upon import.
- **Separation of Evidence and Derived State:** Future AI-extracted summaries or project graphs (e.g., via Meta Muse Spark) are isolated in a dedicated extension namespace (`voidzone`), never overwriting original conversation evidence.

## 2. Specification of Logical Fields

### A. Archive Identity
| Property | Type | Description |
|---|---|---|
| `format` | `"voidzone.continuity.archive"` | Required. Canonical format discriminator. |
| `schemaVersion` | `"1.0"` | Required. Semver string identifying the specification version. |
| `archiveId` | `string` (UUID v4 / URN) | Required. Stable unique identifier for this archive instance. |
| `createdAt` | `string` (ISO-8601) | Required. Timestamp when the archive file was generated by VOIDZONE. |
| `updatedAt` | `string \| null` (ISO-8601) | Optional. Timestamp of the most recent user edit or re-export. |

### B. Source Metadata & Provenance
| Property | Type | Description |
|---|---|---|
| `source.platform` | `string` | Name of the source assistant (e.g. `"claude"`, `"chatgpt"`, `"gemini"`, `"other"`). |
| `source.captureMethod` | `enum` | `"manual_paste" \| "file_import" \| "supported_connector" \| "api_import" \| "unknown"`. |
| `source.title` | `string \| null` | Conversation or project title provided by user or extracted from page. |
| `source.url` | `string \| null` | URL of the source page, if available and appropriate to store. |
| `source.capturedAt` | `string \| null` | Timestamp when the source data was captured or imported into VOIDZONE. |
| `source.provenance` | `enum` | `"user_provided" \| "source_extracted" \| "inferred" \| "unknown"`. |

### C. Completeness Semantics
Completeness is an explicit, audited state:
- `"unknown"`: Default for all manual text paste, file imports, or unverified sessions where total message pagination cannot be mathematically proven.
- `"partial"`: Confirmed incomplete capture (e.g., user stopped mid-session, tab closed before pagination completed).
- `"complete"`: Proven complete capture (e.g., confirmed full-history pagination where `has_previous_page === false`, or explicit user confirmation).

| Property | Type | Description |
|---|---|---|
| `completeness.status` | `"complete" \| "partial" \| "unknown"` | The verified completeness state. |
| `completeness.reason` | `string` | Human-readable explanation of why this completeness status was assigned. |
| `completeness.messageCount` | `number` | Must strictly match the length of `conversation.messages`. |
| `completeness.sourceConfirmed` | `boolean` | `true` only if verified by the source platform API or user confirmation. |
| `completeness.lastCheckpoint` | `string \| null` | Checkpoint or sequence cursor when available. |

### D. Original Transcript & Messages
- `rawTranscript` (`string`): The exact, unedited raw text provided to VOIDZONE.
- `conversation.messages` (`ArchiveMessage[]`): Ordered sequence of discrete turns.
  - `id` (`string`): Message identifier (e.g. `"msg-1"`).
  - `sequence` (`number`): 1-based sequential integer (`1, 2, 3...`) with no gaps.
  - `role` (`"user" \| "assistant" \| "system"`): Speaker classification.
  - `content` (`string`): Exact message content.
  - `timestamp` (`string \| null`): ISO-8601 source timestamp. **Must remain `null` if not provided by source; NEVER invented.**
  - `sourceMessageId` (`string \| null`): Native ID from source platform, if present.
  - `isSynthetic` (`boolean`): Set to `true` when generated via VOIDZONE heuristic parsing.

### E. Canonical Source Hashing & Integrity
To prevent cross-platform newline discrepancies, canonical serialization normalizes line endings:
```text
VOIDZONE_CANONICAL_V1
<rawTranscript with \r\n normalized to \n>
===MESSAGES===
<sequence>|<role>|<content with \r\n normalized to \n>
---
...
```
The canonical string is encoded to UTF-8 and hashed via SHA-256, producing a 64-character lowercase hexadecimal string stored in `integrity.sourceHash`.

| Property | Type | Description |
|---|---|---|
| `integrity.algorithm` | `"SHA-256"` | Hash algorithm used. |
| `integrity.sourceHash` | `string` (64 hex chars) | Deterministic cryptographic hash of canonical source content. |
| `integrity.canonicalFields` | `["rawTranscript", "messages"]` | Array of source fields covered by the hash. |
| `integrity.verified` | `boolean` | `true` when recomputed hash matches upon import. |

### F. VOIDZONE Extension & Continuation Instructions
| Property | Type | Description |
|---|---|---|
| `voidzone.instructions.targetPlatform` | `string` | Target AI platform (default: `"chatgpt"`). |
| `voidzone.instructions.transferPrompt` | `string` | Structured continuation prompt containing guidelines and source transcript. |
| `voidzone.instructions.isEdited` | `boolean` | Indicates whether the user edited the default transfer prompt. |
| `voidzone.derivedProjectState` | `null` | Reserved for future Meta Muse Spark state extraction. |
| `voidzone.reviewStatus` | `"unreviewed" \| "reviewed" \| "unavailable"` | Human review status of derived artifacts. |

  },

      {
        "id": "msg-1",

## 4. Legacy Migration & Compatibility Policy

VOIDZONE maintains strict backward compatibility with packages created by the initial hackathon prototype:
- **Legacy Signature Detection:** When an imported JSON has `schemaVersion: "1.0"` with `transcript` and `transferPrompt` string properties, but lacks `format: "voidzone.continuity.archive"`, the legacy migration adapter automatically activates.
- **Non-Destructive Upgrade:** The raw transcript is extracted, parsed into structured turns, hashed with SHA-256, assigned an honest `completeness: "unknown"` rating, and wrapped into the canonical v1.0 contract.
- **Future Versions:** Any archive with an unsupported `schemaVersion` (e.g. `"2.0"`) is rejected with a structured error.
